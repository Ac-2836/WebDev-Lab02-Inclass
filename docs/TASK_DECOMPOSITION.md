# Work Breakdown Structure (WBS)

| Task | Level | Scope | Constraint | Commit | Deliverables |
|---|---|---|---|---|---|
| **0. Setup** | Big | Establish repository governance | No application scaffold required | — | Keep contract docs in `docs/` |
| 0.1 Add contract docs to repo | Small | Keep contract docs in `docs/` | `project-rules.md` and `TASK_DECOMPOSITION.md` are mandatory artifacts | `docs(spec): Task decomposition & project rules` | `docs/project-rules.md`, `docs/TASK_DECOMPOSITION.md` |
| **1. Mini-React VNode & Mounting Engine** (Exercise 1) | Big | Build createElement, createTextElement, renderToDOM from scratch | Semantic tags only (no div-soup); XSS-resistant; no `innerHTML` | — | Create `mini-react.js` |
| 1.1 Define VNode & Props interfaces (Contract) | Small | Types for VNode | `readonly` type and props; props holds `children` (VNode[]) and optional `nodeValue`; contract before code | `feat(types): define vnode interfaces` | Create `vnode-interface.ts` |
| 1.2 Implement createTextElement factory | Small | Wrap a primitive as a text VNode | type `'TEXT_ELEMENT'`, `nodeValue: String(text)`, `children: []` | `feat(core): add text vnode factory` | Create `createTextElement` in `mini-react.js` |
| 1.3 Implement createElement flattening & mapping | Small | Build a VNode from (type, props, ...children) | `flat(Infinity)`; drop null/undefined/false; wrap primitives via createTextElement; props defaults to `{}`; return new frozen objects, never mutate inputs | `feat(core): implement createElement factory` | Create `createElement` in `mini-react.js` |
| 1.4 Implement recursive renderToDOM with typeguards | Small | Turn a VNode tree into real DOM | `createTextNode` for text, `createElement` for tags; set props and attach listeners; recurse children; mount with `replaceChildren()`; no `innerHTML` | `feat(core): implement renderToDOM` | Create `renderToDOM` in `mini-react.js` |
| 1.5 Verify checkpoint | Small | Audit mounting and XSS resistance | `<script>alert(1)</script>` as child renders as plain text; Elements panel matches the VNode tree with no orphan nodes; `console.assert(root.querySelector('button') !== null, 'Mount Failed')` | `test(core): add vdom mounting and xss checks` | Create `test-runner.js` |
| **2. Reactive State Machine & Delegation Hub** (Exercise 2) | Big | Custom useState engine, root event delegation, reactive Task Manager | Unidirectional data flow; mandated commit messages in order | — | Create `reactive-engine.js`, `event-delegation-hub.js`, `task-app.jsx` |
| 2.1 Define useState & dispatcher interfaces (Contract) | Small | Types for the state hook and setter | Setter accepts a value or an updater function; contract before code | `feat(types): define state interfaces` | Create `state-interface.ts` |
| 2.2 Implement stateStore array and cursor | Small | Linear state storage outside components | State lives in an external array indexed by a cursor | `feat(state): add state store and cursor` | Create `reactive-engine.js` |
| 2.3 Implement resetCursor | Small | Reset cursor before each render pass | Must run before every component execution | `feat(state): implement stateStore and resetCursor engine` | Modify `reactive-engine.js` |
| 2.4 Implement useState initialization | Small | Set initial value on first call, then advance cursor | Initialize only when the slot is empty; hooks run in fixed order, never inside conditions or loops | `feat(state): initialize state hook slots` | Modify `reactive-engine.js` |
| 2.5 Implement setState via closure | Small | Setter bound to its own cursor index | Capture `currentCursor` at call time; do not read the global cursor later | `feat(state): bind setters to state slots` | Modify `reactive-engine.js` |
| 2.6 Support function updaters | Small | Handle `setState(prev => next)` | If the argument is a function, call it with the previous state | `feat(state): support functional state updates` | Modify `reactive-engine.js` |
| 2.7 Skip identical updates | Small | Avoid needless re-render | Compare with `Object.is`; re-render only when the value changed | `perf(state): skip identical state updates` | Modify `reactive-engine.js` |
| 2.8 Implement setRenderer & triggerRender | Small | Connect state changes to root re-render | Callback registered once; invoked only after an actual change | `feat(state): implement reactive useState dispatcher` | Modify `reactive-engine.js` |
| 2.9 Implement root event delegation hub | Medium | Connect VNodes to one root event listener | Store `__vnode`; support click, input, keydown; traverse bubbling to root; no child listeners | `feat(events): attach root event delegation listener` | Modify `mini-react.js`; create `event-delegation-hub.js` |
| 2.10 Assemble reactive Task Manager | Medium | Configure and bootstrap Vite, then connect the state engine, event hub, and Task UI | Vite/ESBuild JSX transform; runnable `index.html` entry point; `renderApp` lifecycle; task/filter contracts; pure filtering; semantic UI; immutable updates | `feat(ui): assemble reactive todo application` | Create `.gitignore`, `index.html`, `main.js`, `package.json`, `package-lock.json`, `style.css`, `vite.config.js`, `task-types.ts`, `filter-tasks.js`, `task-app.jsx`; modify `reactive-engine.js` |
| 2.11 Verify checkpoint | Small | Audit reactivity and listeners | Mutate state via UI; DevTools shows zero listeners on button children (root only) | — | None |
| **3. Resilient State Machine & Skeleton Loader** (Exercise 3) | Big | Async data component with four states | Eliminate race conditions and inconsistent UI states | — | Create `data-feed.jsx`, `view-state.ts`, `fetch-feed.js`, `skeleton.css` |
| 3.1 Implement resilient data-feed state machine | Large | Build the complete async feed lifecycle | Define ViewState and Item contracts; mock fetch with latency/failure; handle IDLE, LOADING, SUCCESS, ERROR; prevent stale responses; show skeleton and retry; use semantic list markup | `feat(ui): implement multi-state data component with skeleton feedback` | Create `view-state.ts`, `fetch-feed.js`, `data-feed.jsx`, `skeleton.css` |
| 3.2 Verify transitions | Small | Audit state machine behavior | DevTools check of success, forced failure, retry, and rapid repeated triggers; no inconsistent UI | — | None |
| **4. AI Failure Audit** | Big | Report on AI failures found during the lab | Mandatory deliverable (15% of the grade) | — | Create `AI_FAILURE_AUDIT.md` |
| 4.1 Compile AI_FAILURE_AUDIT.md | Small | Turn the logged failures into the report | At least 3 detected failures; each entry uses the slide's format with DevTools proof and manual fix | `docs: add ai failure audit report` | Create `AI_FAILURE_AUDIT.md` |

* RULE: Keep work atomic, but group related sub-tasks into meaningful
  implementation milestones. Commit at the milestone boundary, not after
  every small edit. Preserve exact course-mandated commit messages.
